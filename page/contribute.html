CONTRIBUTOR GUIDE

Ship a task that another agent can actually run.

A DataCall task is a small, reproducible experiment package. Keep the public evidence inspectable, define separate Issue and Solution contracts, and include the verifier that turns an agent's output into a score.

Start with the package format ↓
THE SUBMISSION CONTRACT
01Metadatadescribe the run
02Workspaceshow the evidence
03Evaluationsissue + solution
04Verifiermake the score repeatable
A
Reproducible

Pin the model, dataset, training setup, environment, and metric in metadata.

B
Inspectable

Include the source, configuration, logs, and frozen evidence an agent needs.

C
Verifiable

Ship a testable verifier/test.sh for every evaluation level.

01 / PACKAGE FORMAT

One directory, one complete case.

The validator checks the required paths below. Add supporting files when they help an agent understand or reproduce the failure.

your_task_id/
├── metadata.yaml
├── readme.md                  # recommended
├── workspace/                 # public agent workspace
├── environment/
│   ├── Dockerfile
│   └── hydrate-assets.sh      # optional
└── evaluations/
    ├── issue/
    │   ├── instruction.md
    │   ├── oracle.md           # hidden reference
    │   └── verifier/
    │       └── test.sh
    └── solution/
        ├── instruction.md
        ├── oracle/             # hidden reference
        └── verifier/
            └── test.sh
Required

metadata.yaml, workspace/, environment/, and at least one evaluation.

Recommended

readme.md, historical logs, frozen metrics, and a short case overview.

Grading-only

Oracle files and verifier implementations should not be exposed in the agent workspace.

02 / EVALUATIONS

Two contracts, two kinds of work.

Issue asks for a diagnosis. Solution asks for a repair and a fresh run. Keep the instruction, oracle, and verifier for each level together.

ISSUEevaluations/issue/

Diagnose the run

Ask the agent to inspect the historical snapshot, identify the root cause, and support the diagnosis with concrete evidence. The workspace should remain unchanged.

instruction.mdagent-facing task and deliverables
oracle.mdhidden reference diagnosis
verifier/test.shscore the submitted diagnosis
SOLUTIONevaluations/solution/

Repair and rerun

Ask the agent to fix the defect in the staged workspace, run the designated command in the foreground, and leave the fresh artifacts that the verifier reads.

instruction.mdfixed paths, command, and constraints
oracle/hidden reference materials
verifier/test.shscore the resulting artifacts

04 / WORKSPACE & VERIFIER

Package evidence, not an empty project.

01Workspace

Source code, launch scripts, effective configuration, logs, outputs, and frozen evidence the agent can inspect.

02Environment

A Dockerfile and optional hydration script that prepare the run with the required local assets.

03Verifier

Read the result files named in the instruction and return a deterministic score or pass/fail outcome.

05 / BEFORE YOU PUBLISH

Run the same checks the catalog will run.

Resolve every structural error locally, then exercise both evaluation levels with a known-good fixture.

  1. 01
    Freeze the case

    Capture the workspace, environment, configuration, logs, and held-out evidence.

  2. 02
    Write the contracts

    State the action, constraints, deliverables, and scoring behavior in each instruction.

  3. 03
    Validate and exercise

    Run the structural validator and test each verifier against a known result.

Structural validation
PYTHONDONTWRITEBYTECODE=1 \
python3 -m ptdbench validate path/to/your_task

A task is ready for the catalog when the command passes and its public workspace is usable offline.
