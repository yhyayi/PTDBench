# Qwen3-VL Geo3K：buggy 與 fixed 完整實測報告

8×H800，缺陷組與參考組各 20 步，每組一次實驗。

主要結果：20 步訓推 KL 平均 **0.006590862 → 0.000623229 nat/token**，下降約 **10.58 倍**；最終答對 **355/601 → 370/601**，正確率 **59.07% → 61.56%**。
兩組 step 0 答對分別 343 與 353 題；20 步內淨增加 12 與 17 題，因此最終 15 題差距不能全歸因於訓練修復。
buggy 也未崩潰，訓練 reward 的 20 步平均甚至略高於 fixed；最強的區分證據是訓推一致性，而非短跑 reward。

## 設定與資料

Qwen3-VL-8B-Instruct、Geo3K、GRPO、FSDP2，prompt 2048，response 8192，context 10240，動態 token budget 16384。
Train batch 32、每 prompt 5 條 rollout，即每步 160 條樣本；每次驗證 601 題，n=1。
Actor lr=1e-6，KL coefficient=0.01，兩組均從原始 checkpoint 開始，resume disabled。
上游 commit `483b8a009ba3a97563edee3a19887e4862b8094a`。兩組共用 Accelerate 1.13.0 等相同環境。

## 指標解讀

指標定義與限制：

- `rollout_corr/kl` = 有效 response token 上的 mean(log π_rollout − log π_actor)，是以 rollout 樣本估計的訓推 KL，單位 nat/token；不是最大絕對差。
- `rollout_corr/k3_kl` = mean(exp(Δ) − Δ − 1)，其中 Δ = log π_actor − log π_rollout。這是另一種 KL 估計，不能與凍結測試的 max 誤差混為一談。
- `rollout_corr/log_ppl_abs_diff` 先對每條序列取 mean(log π_rollout − log π_actor)，再取絕對值並在序列間平均。它不是 mean(abs(token log-prob 差))，序列內正負差可抵消。
- `training/rollout_probs_diff_*` 使用 exp(log-prob) 後的機率絕對差，沒有 nat 單位；Pearson 也對機率計算。
- `actor/kl_loss` 是 actor 相對 reference 的 KL loss，與訓推 KL 比較的是不同對象；`actor/ppo_kl` 也不是訓推 KL。
- 本次沒有保存每步的 token mean/max 絕對 log-prob 差，也沒有逐 token log-prob 原始陣列，不能從機率差重建。六案例凍結測試保存了 token log-prob，可計算其 mean/max。
- Geo3K reward = 0.9 × 答案正確 + 0.1 × 格式正確；本次所有 validation 和 rollout 檔案只有 0 與約 0.9 分，沒有格式加分。日誌 `acc` 沿用 reward 分數，不是通常的二元正確率。表中的答對題數由 601 筆 validation JSONL 的 score 核對。
- 驗證只在 step 0、5、10、15、20 執行，其餘步沒有驗證數字；沒有插值或以前次數字填補。
- B/F 為兩次獨立訓練：初始 checkpoint 與超參相同，初始驗證結果並不完全相同；不能把最終差異全部歸因於修復，也不能把同 step 當成相同生成樣本的逐 token 配對。
- 所有跨 step 均值都是簡單平均，並非把所有步的 token 合併後重算。
- 梯度有限且兩組都完成，但這是單次 20 步短跑，未證明長期 RL collapse 或多種 seed 下的泛化差異。通過評測門檻不代表所有 token 的 log-prob 完全一致。
