# Packages whose build needs more than `pip install <pin>`.
#
# Format:  <name> [VAR=value ...] -- [pip args ...]
# The version is never written here: build-env.sh reads it out of
# requirements.txt (pin_for), so the pin stays in one place. Names listed here
# are excluded from the bulk pass and installed one at a time, because pip has
# no way to attach per-requirement build flags inside a requirements file.
#
# apex -- without --cpp_ext --cuda_ext, apex installs as a pure-Python package
# and the C extensions Megatron looks for are simply absent. The one that
# matters here is fused_weight_gradient_mlp_cuda: megatron.core's
# ColumnParallelLinear/RowParallelLinear default to gradient_accumulation_fusion
# =True and raise at construction time if the module cannot be imported
# (megatron/core/tensor_parallel/layers.py). That is a hard RuntimeError during
# model init, not a silent fallback, so every slime task here needs it -- the
# torch_dist conversion in slime_retool's prepare.sh hits it before any
# training starts.
#
# Why not just pass --no-gradient-accumulation-fusion instead: that changes the
# numerics of the backward pass (fp32 accumulation into the weight grad buffer
# vs. torch's default), and this benchmark grades on reproducing specific
# training curves recorded against an image that had apex compiled in. Matching
# the upstream image is the point.
#
# DeepEP is deliberately still absent: it is for MoE all-to-all and every task
# on this environment is dense.
apex -- --config-settings "--build-option=--cpp_ext" --config-settings "--build-option=--cuda_ext"
# torch_memory_saver -- its extension calls the CUDA *driver* API (cuMemCreate,
# cuMemMap) and so links -lcuda. There is no driver in a build stage, which is
# what $CUDA_HOME/targets/x86_64-linux/lib/stubs is for; build-env.sh already
# puts targets/.../lib on LIBRARY_PATH but not stubs, and without it the link
# ends in `cannot find -lcuda`. The recorded soname is still libcuda.so.1, so
# at runtime it resolves to the real driver the container was given.
#
# Scoped here rather than added to build-env.sh's global LIBRARY_PATH on
# purpose: that stubs directory also holds libcublas.so, libcufft.so and
# friends, and putting it in front of every link would let a package resolve
# -lcublas to a conda stub instead of the pip nvidia-cublas wheel this
# environment actually runs on. One package needs the driver stub; only that
# package gets it.
#
# Headers need no entry: the `#include <cuda_runtime_api.h>` that conda's
# header layout breaks is already handled by the CPATH build-env.sh exports
# for every package (it compiles with plain g++, not nvcc, so it gets no
# include path of its own -- unlike apex and transformer_engine).
torch_memory_saver LIBRARY_PATH=$CUDA_HOME/targets/x86_64-linux/lib/stubs:$LIBRARY_PATH --
